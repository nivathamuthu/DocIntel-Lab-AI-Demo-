# Module 7 demo script (90 seconds)

Before recording: rules extracted (`.\make.ps1 extract-rules`). Optionally `docker compose exec web python manage.py eval_codegen` (Gemini, about 3 minutes). Open http://localhost:8010/codegen/.

1. (0:00-0:15) Point at the two cards. "One call writes the code. Another writes tests from the rule text only and never sees the code. The tests run in a separate process; this is a demo sandbox, not a security boundary."
2. (0:15-0:30) Type `12000` in the search box. Tick the rule "flight hours are at least 12000". The amber card appears: "These rules disagree. The generated code returns 'conflict' and does not choose." Its conflict partners (the 11500 rule) are added automatically.
3. (0:30-0:50) Click Generate code. The page shows "Writing the code…", then the attempt timeline fills in. Open Attempt 1: the code, the tests and the pytest output, with failing lines in red if any.
4. (0:50-1:10) Final panel: code and tests side by side. Point at the `conflict` branch that names both rule keys, and at a test comment with the rule key and quote. Click Copy, then Download.
5. (1:10-1:30) Results page, section 7. Read: 5 of 5 cases passed, mean attempts 1.0, conflict surfaced 1 of 1, and the mutation check ran on 2 of 5 cases and caught both. Say the caveat: "When a test fails, a separate call judges it against the rule text. A wrong test is dropped, an ambiguous rule stops the run for review, and the repair may not change a number from the rule. Passing self-written tests still shows consistency with the model's reading, not that the code is right. A person reviews it."
